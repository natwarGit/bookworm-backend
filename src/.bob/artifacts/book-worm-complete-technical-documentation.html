1. Problem Statement

Modern retailers require digital storefronts capable of handling product discovery, personalised recommendations, secure checkout, and reliable payment processing. The challenge is to build a production-ready backend for an E-Bookstore platform that supports the complete customer journey — from browsing a catalogue to confirming a purchase — using AI-assisted development tools to accelerate delivery.

Business Need: An online store where a customer can browse, select, and buy books with flexible payment options, gift point redemption, delivery address management, and a 48-hour order cancellation guarantee.

7. Authentication Flow

Authentication uses a stateless SHA-256 password verification approach suitable for a capstone demo, without adding Spring Security complexity.

StepWhat Happens
1Client sends POST /api/v1/auth/login with email and password
2AuthController validates the request body (Bean Validation)
3AuthService.login() calls UserRepository.findByEmail()
4If user not found → throws BusinessException("Invalid email or password")
5Computes Base64(SHA-256(rawPassword)) and compares with storedHash using MessageDigest.isEqual() (constant-time compare)
6Returns LoginResponse with userId, fullName, role, giftPointsBalance
7Client uses the returned userId as a request parameter in all subsequent calls

8. Order Placement Flow

StepLogic in OrderService
1Fetch User and Cart by userId — throw if cart empty
2For each CartItem: validate stockQuantity ≥ quantity, deduct stock, accumulate total
3Apply gift point redemption: pointsToRedeem = min(requested, userBalance); discount = ₹1 per point
4Build Order entity with orderNumber = "ORD-" + timestamp
5@PrePersist sets orderDate = now() and cancellationExpiryDate = now() + 48h
6Copy CartItems → OrderItems (snapshot price at purchase)
7Save order, award finalAmount × 5% points back to user, clear cart
8Return OrderResponse with eligibleForCancellation: true

9. Payment Flow

StepLogic in PaymentService
1Fetch Order by orderId — 404 if not found
2Reject if order is CANCELLED
3Check for duplicate: if a SUCCESS payment already exists for this order → 400 error
4Parse paymentMethod string → PaymentMethod enum (CREDIT_CARD / DEBIT_CARD / UPI / WALLET)
5Generate unique transactionId = "TXN-" + UUID(16 chars uppercase)
6Set status = SUCCESS, save Payment to DB
7Advance order status: PLACED → PROCESSING
8Return PaymentResponse with transactionId and confirmation message

13. Key Business Rules

RuleImplementation
48-Hour Cancellation WindowcancellationExpiryDate = orderDate + 48h set in @PrePersist. isEligibleForCancellation() checks now() < expiryDate.
Gift Point Redemption1 point = ₹1 discount. Max redeemable = user's current balance. Deducted on order placement.
Gift Point Award5% of finalAmount awarded back to user after each successful order.
Stock ManagementStock decremented on order placement. Restored on cancellation.
Duplicate Payment GuardChecks for existing SUCCESS payment on same orderId before processing.
Price SnapshotpriceAtPurchase stored on OrderItem — price changes don't affect old orders.
Delivery DateComputed dynamically: LocalDate.now() + deliveryLeadDays. eBooks = "Instant Delivery".
